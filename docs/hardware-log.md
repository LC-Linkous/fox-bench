# Hardware log

What was verified on a real board, when, with which firmware — the evidence
behind a target's `status` and a template's `boards_tested`. One entry per
bench session. Record what was checked and how (by ear on a handheld, an
S-meter at distance, a power meter, a scope), not just "works".

Commit hashes are the fox-bench commit the firmware was built from; the
Board tab shows them for the site's UF2 (`foxbench-picofox.json`).

`python3 tools/bench_queue.py` reads this table against the catalog and
prints what the next sessions have to show: a stable target whose last row
predates the firmware the catalog ships is a **re-run**; an experimental
one is a **first session**. CI fails if a stable target has no row at all.
A row is matched to a board by the `log_names` in its `hardware/*.json`
(or, failing that, the descriptor's name), so name the board the same way
each time.

## Not yet verified on hardware

- foxlib-c: attenuator dB per step (needs an S-meter at distance or a power
  meter — `tools/atten_sweep.py` runs the sweep and keeps the table) **and**
  the attenuator word format (`player.c atten_write` sends 8
  bits; the datasheet reading in `docs/picofox.md` describes a
  longer word — possibly the same question); `radio.correction_ppm` (applied
  since 0.1.8, not measured against a counter); `i2c_errors` recovery path exercised only by construction, never
  seen to fire; watchdog timeout path (a hang has not been provoked).
- Templates on the PicoFox other than morse-songs and morse-sstv: the
  firmware runs them in the host simulation, not yet on air.
- The network foxes on the chip targets still without a row: the Waveshare
  ESP32-S3-Nano (`esp32s3`, the Arduino Nano ESP32 build; `board.LED` to
  verify, RGB `LED_RED/GREEN/BLUE`) and the Arduino Nano 33 BLE Rev2
  (`nrf52840`, `arduino_nano_33_ble_rev2`; BLE only, CircuitPython by
  `bossac`). The XIAO C3 (BLE), C6, C5 and S3 have their rows above; the
  C5's pin names follow the DevKitC-1 build's `IOxx` naming, confirmed
  2026-11-24. Deep sleep across a wake, a 5 GHz access point (needs a build
  newer than 10.3.2) and the LED's blink direction on the C5/C6
  (`active_low`) are the open items on the boards that have run.
